# 前端演示（pipeline-demo.html）

单文件、零依赖，双击即可在浏览器打开。里面**没有任何后端调用**，所有阶段切换是前端模拟的，数据取自这一批真实跑批结果。

## 打开方式

```bash
open demo/pipeline-demo.html
```

带参数可以直接看结果态，省得每次点一遍：

| URL | 效果 |
|---|---|
| `pipeline-demo.html` | 初始上传态 |
| `pipeline-demo.html?auto` | 七个阶段全部完成，停在最后一步 |
| `pipeline-demo.html?auto=3` | 全部完成，但停在「术语」这一步 |

## 可交互的点

1. 点拖拽区 → 载入示例文件，右侧顶部按钮变为可用
2. 点「开始准备」→ 七个阶段依次跑，侧栏圆点、顶部进度、日志同步变化
3. 点侧栏任一已完成阶段 → 右侧换成该阶段的产物预览
4. 点「从这一步重跑」→ 该阶段之后重置并重跑
5. 勾选顶栏「演示第 ④ 步失败」→ 跑完会停在失败态，看阻断效果

## 这一版想对齐的几件事

演示里每个决定都摆在明面上，逐条可以推翻：

| # | 当前做法 | 想确认的 |
|---|---|---|
| 1 | **规范化放在最前**（原设计里没有这一步） | 客户导出的空列与 speaker 缺失，应该在流水线内修，还是要求客户改导出？ |
| 2 | 七个阶段**自动连续跑** | 还是要每步停下等人点「确认继续」？ |
| 3 | 失败即**阻断**，但保留前序产物 | 阻断后是原地重试，还是必须从第一步重来？ |
| 4 | 每阶段预览一块内容（表 / 条形 / 单元格 / 断言） | 预览粒度够不够？要不要支持看全量？ |
| 5 | **单批次单页面** | 需不需要批次历史列表（跑过的批次可以回看）？ |
| 6 | 自检结果分「阻断 / 告警」两级 | 哪几条该是阻断？现在是 7 阻断 2 告警 |
| 7 | 侧栏七个阶段**常驻可见** | 阶段多了以后（比如加「回灌」）要不要折叠？ |

## 说明

- 颜色沿用 `static/css/style.css` 的调色板，之后接 Flask 模板时可以直接复用样式变量。
- 数据是写死的常量（`STAGES` 数组），接后端时把这个数组换成接口返回即可，渲染逻辑不用动。
