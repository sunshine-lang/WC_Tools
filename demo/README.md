# 前端演示 v2（pipeline-demo.html）

单文件、零依赖，双击即可打开。没有后端调用，阶段推进是前端模拟的，数据取自这一批真实跑批结果。

## 打开方式

```bash
open demo/pipeline-demo.html
```

带参数可以直接跳到某个状态，省得每次点一遍：

| URL | 效果 |
|---|---|
| `pipeline-demo.html` | 初始上传态 |
| `pipeline-demo.html?lib` | 直接打开资料库 |
| `pipeline-demo.html?review=2` | 前两个节点完成，第 3 个停在「待确认」 |
| `pipeline-demo.html?auto` | 七个节点全部完成 |
| `pipeline-demo.html?auto=5` | 全部完成，停在「TM 参考」 |

## 这一版加了什么

### 1. 项目层

左上角是项目选择器，点开可以新建项目（名称 + 语言对）。新建后资料库是空的，需要逐个上传。

一个项目 = 一套资料库 + 一套规则；批次挂在项目下。

### 2. 资料库（一项目一套）

侧栏底部入口，五个槽位：

| 槽位 | 必需 | 现在有什么 |
|---|---|---|
| 术语库 | 必需 | WC术语库.xlsx · 161 条 |
| 记忆库 | 必需 | wcde.tmx · 13,661 对 |
| 人设 / 关系 | 选填 | 听风城堡-角色人际关系.md · 22 角色 |
| 游戏背景 | 选填 | 未上传 |
| 风格指南 | 选填 | 未上传 |

**直接替换语义**：点「替换」就地换掉，不留历史版本（按当前决定）。演示里点上传会模拟填入一个真实文件名。

### 3. 逐节点确认

不再一口气跑完。节点分两类：

```
自动通过：规范化、分类、术语        ← 结果可机器判定
需要确认：上下文、术语筛选、TM、自检  ← 需要人判断
```

需要确认的节点跑完会停在「待确认」，页面上多出一块 **⚠ 确认前看一眼**，列出这一步具体该核对什么，然后才是「确认并继续 →」。

### 4. 失败态

第 ④ 步失败时（顶栏有开关可以模拟），底部给两个按钮：

```
[重试本步]      跑完停在待确认
[重试并继续]    跑完自动进下一步
```

前序产物保留，侧栏前面几个节点仍是绿的。

## 想对齐的决定

| # | 当前做法 | 待确认 |
|---|---|---|
| 1 | 规范化放在最前 | 该由工具擦屁股，还是要求客户规范导出？ |
| 2 | 三个节点自动通过 | 这个划分同意吗？要全部需要确认也可以 |
| 3 | 确认页给「看什么」清单 | 清单内容对不对，是不是你要核对的东西 |
| 4 | 失败给两个按钮 | 「重试本步」和「重试并继续」够不够 |
| 5 | 资料库直接覆盖 | 已按你的决定；如果以后要历史版本，需要加版本表 |
| 6 | 单批次单页面 | 要不要批次历史列表（跑过的批次可回看） |

## 接后端时要补的

- **批次状态落盘**：逐节点确认意味着人会离开页面，`workspace/<批次>/state.json` 必须记录每节点状态、产物路径、确认时间。现在任务状态在内存里，重启即丢。
- **阶段定义来自后端**：`STAGES` 数组现在是写死的常量，接后端后换成接口返回，渲染逻辑不用动。
- **资料库槽位落到项目配置**：现在 `LIBRARY` 是常量，实际应存在项目记录里。
