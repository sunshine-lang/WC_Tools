<!-- TITLE: 03 · 装饰物名称 -->
<!-- CATEGORY: 装饰物名称 -->
<!-- OUTPUT: 03_装饰物名称.md -->

<!-- FOCUS -->
本场景处理城堡或活动中的装饰物名称。名称应自然、简短，能与具体物件、活动主题及相关对白对应；兼顾音乐梗、双关等文字趣味。不处理集卡套名与卡名、活动 UI 标题或对白正文。

<!-- TASK -->
在本次 ready 文件中，按用户指定范围处理 `分类 = 装饰物名称` 的记录，将 `game_text_en` 翻译或审校为 `game_text_de`。先阅读本行名称、实际 Context 和可确认的图片，再核对同活动相关名称；任务模式以用户本次消息和共用规则为准。活动、行数、长度、图片及术语／TM 情况均取自实际输入，不要求单独拆表、制作图片映射文件或新增交接附表。

<!-- RULES -->
1. **识别具体装饰物及关联范围。** Key 用于定位活动与物件，不是待译正文，也不能只按物理相邻行推测关系。例如 `mdnew_forestconcert_mdnew_decoration_name_18` 可与同活动的 `_mdnew_decoration_18_1` 等对白核对；其他活动的相同编号不能合并。编号本身不说明等级、稀有度、建造先后或数量。缺少关联内容时不补造剧情。
2. **分别使用名称、图片和对白的证据。** 本行英文表达命名意图；对应图片帮助辨认外形与物件；对白中的明确描述可解释用途、物件组成、名称指代或谜题。Context 可能只有活动介绍，也可能有具体对白，必须实际读取，不能预设每行都一样。只引用与本物件有可靠关联的内容；活动背景不能代替单个物件的证据。
3. **确认图片归属，不设置全局优先级。** 可用 ready 中实际能读取的图片或随附素材，结合连续色块、图片位置、Key 和版本判断归属；整张活动图不等于每件物品的特写，同色的非连续区域也不自动同组。图片缺失、读不到或对应不明时说明局限，不假装看过。源文或关联对白已足够明确时可先给保守候选；物件判断仍有歧义才列为待确认。图文实质冲突时列出证据和待确认点，不擅自改成另一物件；针对某个 Key 的客户许可只在其范围内适用，不能推广成“图片永远优先”。
4. **灵活命名，保留识别依据。** 可以意译、调整词序或用自然的德语表达重现名称的效果，不必逐词对应。保留能识别本物件的关键特征；原名没有明确物件类型时，不强制补出一种猜测的家具或设施。不能为了好听或押韵替换乐器、动物、植物或装置，也不加入没有依据的颜色、材质、功能、等级与卖点。原文或明确对应图片已有的事实可以帮助命名，但不把所有画面细节堆进名字。
5. **文字趣味与谜题线索一起判断。** 先识别普通描述、头韵、谐音或固定表达，尝试自然可懂的德语效果；不要求复刻英语发音，也不预先判定直译一定错误。无法兼顾时保住对象和关键含义，再说明趣味损失。如果名称与对白谜题共用某个词、声音或象征，需一起理解；不能只为名称顺口就破坏后续谜题的可理解性。不要把对白中后来揭晓的答案、奖励位置或秘密写进名称。
6. **保持跨文案名称一致，尊重修改范围。** 明确指向同一装饰物正式名称时，遵循客户已确认名称及适用术语；德语在句中的格、数、冠词可按语法变化，不要求逐字复制名词形式。普通描述、同类物件或相似英文不自动视为正式名称。先前仅由模型生成的译名仍是候选。名称与对白或 UI 译名冲突时，只修改本次获准的单元格，在简短问题说明中标出相关 Key 和建议统一的方向；本场景不越界改写对白，也不新增名称表作为交付前置条件。
7. **系列风格一致，但不一律套主题词。** 依据当前活动资料确定轻松、幽默或其他适用语气；同一概念用词保持一致，不同物件保留区别。不能把所有活动都套成森林音乐会，也不能给每个名称强加“音乐”“森林”“可爱”等词。相同源名或对象的重复不自动判错，只有不同对象因翻译被混为一谈时才需调整或说明。
8. **名称文体与长度按实际约束处理。** 名称通常简短，能在列表或场景中独立显示；保留原名允许的短句、感叹或问句形式，不强制去掉原有标点或冠词。德语大小写、参数、标签和换行遵循共用规则，不附梗的解释。逐行读实际 `limit`，不把历史批次的 30 写成永久上限，也不自动套用棋子 28 字符或支付项标题规则。超长时选更紧凑的表达，不能硬截术语、换物件或删掉谜题所需的区分信息；仍不满足时记录具体上限、长度及原因。
9. **最后回看关联名称。** 核对本物件与同活动相关名称、对白引用的对应关系，检查明显撞名、指代变化和无依据的增删。英文源文、Context、图片和其他原始字段保持；不因为重新分组阅读而重排行序。模式 A 不改已有德语；模式 B/C 的修改必须有具体依据，已有译文、TM 和示例都不能自动视为已批准结果。

<!-- EXAMPLES -->
| 输入或情况 | 应采用的判断 |
| --- | --- |
| `Music-Go-Round` 的关联对白明确提到 carousel | 用名称与对白共同确认旋转游乐装置及音乐关联；不能只按字面理解成“音乐到处走”，也不必因缺图就假装完全没有物件依据。具体动物造型仍需相应证据。 |
| `Harp and Soul`，同段出现 `follow your harp`、竖琴盒与心形符号 | 结合竖琴与心的词语联系考虑名称，保留与谜题呼应的可能；不能随意换乐器，或把“钥匙藏在心形旁”的后续发现提前写入名称。涉及德语谜题重构时说明与对白需要共同审校。 |
| `Percussion Carriage` 在对白中被直接称为谜题名，随后说明马车里有 drum kit | 保留打击乐与马车的对应，核对对白正式名称的用词；不能译成只剩“音乐舞台”的泛称，也不把玩法说明全部塞进名称。 |
| `Singing Sprites` 只有活动概述，没有可确认的物件图或具体对白 | 不凭活动主题确定精灵的形态、材质或功能；普通名称中的 Sprites 需要按语义翻译，与必须原样保留的 `<sprite …>` 图片标签不同。关键物件含义不明时说明不确定性。 |
| 只有森林音乐会背景，`Polka Pachyderm` 的对应图片无法确认 | 可以理解音乐与动物的命名方向，但不据此声称看到某种雕像或材质；不能把示例中的某个德语动物名当成客户已确认名称。 |
| 英文名指灯，候选图片看似树篱，且映射没有核实 | 先核对图片是否属于这个 Key 及版本，列出冲突；不能仅凭附近图片就把名称改成树篱。 |
| 同一名称在已提供的对白译文中采用另一说法 | 核对是否同一对象及是否有已批准译名，给出具体关联记录；只处理本场景获准的名称单元格，不擅改对白或宣称全项目已统一。 |
