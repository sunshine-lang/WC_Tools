<!-- CATEGORY: 活动 UI 与商店文案 -->
<!-- OUTPUT: 01_UI与商店.md -->

<!-- FOCUS -->
本场景包括活动标题与说明、引导、成功／失败提示、册名与副标题、礼包及商店文案。目标是功能清楚、表达日常、名称有主题感，并满足适用的长度约束；不处理集卡单卡名称、装饰物名称或角色对白。

<!-- TASK -->
在本次 ready 文件中，按用户指定范围处理 `分类 = 活动 UI 与商店文案` 的记录，将 `game_text_en` 翻译或审校为 `game_text_de`。先区分每行的功能，再决定表达；同一界面的标题、说明、操作及状态文案一起阅读。输入文件名、行数、模式和图片情况均以本批实际材料为准，不要求预先抽取试译表。

<!-- RULES -->
1. **先辨功能，再选文体。** 标题、册名、副标题和礼包名采用自然、简短的命名表达；不强制把所有标题改成名词短语。按钮直说操作，引导说明做什么及目的；规则说明保留对象、条件、数量与奖励。标题是否带句号或感叹号按源文和客户要求，不凭“标题通常不带标点”删除原有符号。
2. **区分状态与阶段。** `_pre_`、`_complete_`、`_success_`、`_fail_` 等 Key 只辅助识别功能，以本行英文和相关说明共同核对。完成某阶段不等于整个活动结束；结束不必然是失败。不能增加“全部完成”“奖励翻倍”“立即领取”等原文没有的信息，也不改变原文的鼓励或庆祝语气。
3. **同一对象保持一致。** 用 Context 核对同活动、同界面中反复出现的名称、对象和称谓。共享活动词不代表所有标题必须译成同一个名称；不能把失败文案套用成功提示的语气，也不能把另一活动的机制带入当前行。空 Context 时仅依据当前源文及明确提供的材料。
4. **幽默和创意服务于含义。** 分清谐音、拼词、头韵和普通主题词；在对象与功能不变的前提下，尝试自然的德语文字趣味，不要求复制英语发音。没有合适表达时优先保意思，记录确实损失的笑点或命名效果；不要预先宣布某个梗“必然无法翻译”，也不把所有押头韵标题都标成双关失败。
5. **商店与礼包不增加承诺。** 可以保留原文的吸引力和节日氛围，但不能新增折扣、稀缺性、免费、最划算或购买号召。“Offer”并不自动意味着降价。源文没有操作指令时，不为增强营销效果自行补一句。
6. **图片用于核对具体对象。** 有对应截图时参考物件、位置和系列；连续色块、图片锚点与 Key 可以共同支持归属，不能把全表同色行合为一组，也不能把组内每张图用于每个 Key。缺图不妨碍含义明确的纯文本 UI；仅在关键判断依赖缺失或无法对应的图片时标记 `missing_image`／`image_text_conflict`，不声称已经看图。
7. **长度按用途确定。** 行级 `limit` 优先读取；适用的客户上限包括剧情标题 45 字符、支付项标题 30、支付项描述 45、Google Play Slogan 80（德语），不能把所有活动标题认作剧情标题，也不能凭 `offer_` 就认定是支付项。商店页的“含空格 500 字以内”保留客户原口径，不解释为 500 个德语单词；没有明确计数方法时记录待确认。未明确用途的空 limit 文案保持简洁，不臆设上限。
8. **称谓和无 Key 行。** 不为简短 UI 强加人称；确需称呼玩家时按共用规则处理。`key` 为空但有源文、能按原始工作表和行号或已有 ID 定位的行照常处理；功能或活动归属不明才记录语境问题，不能仅因没有 Key 跳过或猜造 Key。

<!-- EXAMPLES -->
| 输入或情况 | 应采用的判断 |
| --- | --- |
| `Merge items to earn keys and unlock the next stage.` | 保留“合成物品 → 获得钥匙 → 解锁下一阶段”的因果链；不能只剩“合成获得奖励”。 |
| `Moonlit Memories Complete!`，关联说明允许继续探索拿奖励 | 保留标题中的完成状态；结合说明理解为对应内容完成，不能扩写成整个活动关闭。 |
| `Pawsome Offer` | 识别猫爪意象与夸赞语气的拼词；可尝试德语趣味命名，但不能把 Offer 擅自升级为折扣或最低价承诺。 |
| `Osmanthus Oddities` | 保留桂花相关对象和新奇感；有头韵不等于必须改成“月亮”主题，也不强行凑德语头韵。 |
| `Playtime's Over` 且 limit 为空 | 表达游玩结束；不自动增加失败责备、购买号召或 30 字符硬上限。 |
