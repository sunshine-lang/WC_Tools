# WC 翻译提示词

## 当前流程

按用户在 2026-10-21 明确的流程执行：将工作台准备好的 ready 文件、prompt 和游戏介绍一起交给 WorkBuddy 翻译；翻译结果由用户结合 DeepL 和译员版本进行抽检。目前准备了“通用提示词＋四份场景提示词”和“一份汇总版提示词”两种方案，等待实际对比，不预先认定哪种更好。

不要求先制作小样本试译包，不要求独立交接说明、manifest 或固定的三份附表。ready 文件、客户资料和工作台批次保持原样，提示词直接适配实际输入。

## 交给 WorkBuddy 的材料

新生成的活动对白 Context 使用「【场景结构】＋【情境与基调】」，结合当前项目人物资料与整组英文形成场景解释；翻译时仍须回读同段英文，不能将分析直接当作台词或覆盖原文。旧 ready 文件不会自动更新。

**方案一：通用提示词＋四份场景提示词。** 使用 [WC_UI翻译提示词_分场景版](../../WC_UI翻译提示词_分场景版/) 目录中的五个文件，一次性交给同一个翻译任务：

- [00_通用提示词.md](../../WC_UI翻译提示词_分场景版/00_通用提示词.md)：沿用 RO 的角色设定、任务目标、参考资料、翻译规范及交付栏目，统一任务模式、目标语言、术语／TM、格式、长度和跨场景协调。
- [01_UI与商店.md](../../WC_UI翻译提示词_分场景版/01_UI与商店.md)：UI 与商店场景规则和示例。
- [02_集卡名称.md](../../WC_UI翻译提示词_分场景版/02_集卡名称.md)：套组与卡片命名规则和示例。
- [03_装饰物名称.md](../../WC_UI翻译提示词_分场景版/03_装饰物名称.md)：物件、相关对白与名称规则和示例。
- [04_剧情与活动对白.md](../../WC_UI翻译提示词_分场景版/04_剧情与活动对白.md)：对白、人物、分段与谜题规则和示例。

**方案二：汇总版提示词。** 只使用 [WC_UI翻译提示词_汇总版.md](../../WC_UI翻译提示词_汇总版.md)。两种方案均另附同一份 ready 和游戏介绍。

本次分场景版与汇总版采用相同的共用规则、场景规则及判断示例，仅调整文件组织、标题和必要引用，便于比较组织方式。原 `dist/` 四份完整英德提示词仍保留用于单场景任务；其中已经包含共用规则，不能误当成这次方案一的四份场景专用文件，否则会额外引入规则重复和内容差异。

1. **ready 文件**：使用实际下载的准备结果，不限定文件名；保留分类、Context、生效术语、无效术语、TM 参考及其他原始字段。
2. **翻译 prompt**：按方案一提交五个文件，或按方案二提交一份汇总版；不要在同一轮同时提交两套。每一行只采用其场景规则，不把四种文体要求同时套用，范围外记录保持。
3. **[游戏介绍](../../WC游戏介绍.md)**：用于理解游戏背景，不据此增加原文没有的信息。客户硬规则已整理到 prompt；如有新答复或具体人设需要使用，再随任务补充。

两种方案都由 WorkBuddy 按分类处理，汇总到一份保持原表结构的结果文件；不要让四次独立处理互相覆盖。未获准的记录和未分类记录保持原值，问题单独说明。

发给 WorkBuddy 时，在消息里说明目标语言、真实目标列，以及本次是补译、审校还是指定范围重译、是否允许覆盖已有译文，不需要另写一份任务文件。默认补译仅处理空目标；不能因为当前表有 30 行空值就把后续项目流程固定为只翻这 30 行。用于抽检的译员版本保留为独立对照文件。新分场景版与汇总版均默认英译德，并提供其他目标语种的切换规则；换提示词不代表工作台已经生成对应语言的 ready。

## 对比测试时保持一致

- 两个独立新会话使用同一模型、同一 ready 输入、游戏介绍、目标语言、范围、模式和可控参数；不把第一轮的输出作为第二轮输入，也不将第一轮结果透露给第二轮。
- 测试范围应实际覆盖四类内容。默认补译只处理空目标；若只有 UI 行为空，就无法评估另三种场景。可由用户准备四类均有待译内容的测试副本，或明确相同的重译范围，本次未清空任何 ready 内容。
- 两边同样处理译员参考答案的可见性。用于独立对比时，译员版本留在用户侧；若输入本来包含原译或该批参考答案，应说明这是带参考的测试，不能称为盲译。
- 用同一批行比较含义、术语、文体、名称一致性、谜题、格式与长度。DeepL 只作参考；一次结果可以用于发现问题，不足以断定一种组织方式稳定更优。

ready 表已有 `row_id` 时保留；没有时保持完整工作表与原行位置，不强制添加 ID 或拆成新表。只有确需分段处理时才保留原始位置映射，最终仍按原表位置交回。

图片以 ready 文件或本次实际随附素材为准。图片与 Key 的连续色块、位置和系列关系有依据才使用；不能凭“文件里有图”就假设每张图都能对应每行。

## WorkBuddy 的交付

- 另存翻译结果，不覆盖 ready 输入；仅修改获准的目标语言单元格。
- 简短说明实际处理数量和未解决问题，保留可定位的工作表、原行号、Key 或已有 ID。
- 不强制生成三份附表；问题较多时可另附简短问题清单。
- 不把自身检查结果写成用户已经完成 DeepL 对照或译员抽检。

用户收到结果后，以原始英文为依据，结合 DeepL 和译员版本核对含义、用词、语气、术语及长度等差异，将具体问题反馈到对应场景的 prompt。当前没有执行这一步。

## 文件维护

```text
prompts/
  base.md                 # 四类共用规则
  scenes/
    01_ui_store.md        # UI、活动与商店
    02_card_name.md       # 集卡名称
    03_decoration_name.md # 装饰物名称
    04_dialogue.md        # 剧情与活动对白
  dist/                   # 生成的完整 prompt，交给 WorkBuddy
  build.py                # 重新生成 dist
```

- 修改共用规则用 `base.md`，修改文体规则用对应 `scenes/*.md`。
- 运行 `python3 prompts/build.py` 同步四份完整文件；不手改 `dist/`。
- 上传完整 prompt 即可，不再同时上传 base 和场景源文件，避免规则重复。

新分场景版和汇总版位于 `WC-UI/`，不由上述 `build.py` 生成。本次将汇总版的共用部分与四段场景规则拆分并核对一致；以后修改任一方案时，应同步核对另一方案。如果刻意分别优化两套规则，应注明此后比较的是整体提示词方案，不能把差异只归因于文件拆分方式。提示词正文只保留执行规则，测试操作说明放在本 README。
